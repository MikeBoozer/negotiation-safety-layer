# Scenario data

The N2 hardening run replaces the published experiment's **single** negotiation
situation with a set of distinct ones. These are the candidate sets and the
prompts that produced them.

Nothing here is wired into the harness yet. All of it is pre-registration
material awaiting human review.

## Files

| File | What it is |
|---|---|
| `generation-prompt.md` | The prompt used to produce the candidate batches. Paste-ready. |
| `critic-prompt.md` | Prompt for having a *different* model attack a batch before a human reviews it. |
| `enrich-prompt.md` | Per-scenario prompt for rewriting a thin `cp_situation` so the buyer can actually tell situations apart. |
| `scenarios.generated-flash.json` | **Candidate set — preferred.** 20 situations, Gemini 3.6 Flash. |
| `scenarios.generated-pro.json` | **Candidate set — not selected.** 20 situations, Gemini 3.1 Pro Preview. |
| `scenarios.draft.json` | **Superseded.** The first, hand-written 17. Retained as the source of S0. |

Rendered, reviewable versions of the two candidate batches are in
[`../../../docs/`](../../../docs) as `REVIEW-scenarios-flash.md` and
`REVIEW-scenarios-pro.md`, generated by `harness/make_review_doc.py`.

## Provenance

LLM generation is not reproducible — these APIs expose no seed — so no third
party can regenerate this text and the record below *is* the audit trail. Both
runs used an identical prompt, so the batches differ by model alone.

| Batch | Model ID | Date | Thinking | Grounding |
|---|---|---|---|---|
| `scenarios.generated-pro.json` | `gemini-3.1-pro-preview` | 2026-08-10 | High | off |
| `scenarios.generated-flash.json` | `gemini-3.6-flash` | 2026-08-10 | High | off |

### Schema migration, 2026-08-13 — the one edit made to the raw arrays

The batches are otherwise the generators' raw output. **One mechanical change has been applied to
both:** the field `concession_is_immoral` was renamed to `concession_harms_third_party`, because the
prior-art paper this work sits beside uses the former name for a *different construct* (the demanded
act being immoral, rather than the concession harming a third party). Rationale and the verbatim
prior-art definition are in `generation-prompt.md`.

**No situation text was altered** — the diff is exactly 20 key lines per file, and that is checkable
with `git diff`. Content edits from review will land in a separate candidate file, so they stay
visible as edits rather than baked into the generator output.

Generated outside the Claude family on purpose. The N2 run compares counterparty
model families, and scenarios written by a family under test would entangle "this
model behaves differently" with "this model is handling its competitor's prose" —
two explanations nothing separates after the fact. (The headline arm contrast is
unaffected either way: it is measured *within* each scenario, so the generator
cancels.)

## Why the rejected batch is kept

Both batches scored identically on everything mechanical — balance 10/10 on all
three axes, prefilter 20/20, ban list clean. The Pro set was not selected on a
qualitative ground the gate cannot score.

The counterparty model is shown the `cp_situation` field and **nothing else** —
not `title`, not `domain`, not `our_context`. Measured on that field:

| | good named with a single bare word | no added context | at real risk |
|---|---|---|---|
| Pro | 20/20 | 10/20 | **10 of 20** |
| Flash | 2/20 | 10/20 | **1 of 20** |

Pro's *"Toxic soil cleanup hours for a residential zone"* and *"Overtime labor
hours from a workers' union"* both reach the buyer as `"you are buying $SIZE
hours"` — identical. Its titles are more varied than Flash's; the buyer never
sees them.

Pro retains one advantage worth mining: more variety in the *kind* of good
(shares, inspections, licences, acreage, event access, against Flash's mostly
physical goods). Any scenario lifted from it needs its `cp_situation` rewritten
to name the good properly.

## Before using any batch

```
python harness/check_scenarios.py --json nsl/scenarios/data/<batch>.json
```

The gate is generator-agnostic and costs nothing. Its load-bearing check is that
`our_context` alone trips the strategic marker set: `EncounterDetector.classify`
returns `is_strategic=False` **without an LLM call** on a prefilter miss, so a
scenario that missed would auto-label its quiet episodes non-strategic — hardest
in exactly the low-threat arms the headline contrast rests on.
